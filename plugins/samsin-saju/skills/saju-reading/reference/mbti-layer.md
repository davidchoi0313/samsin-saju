# MBTI 개인화 레이어 계약 (mbti-layer.md)

> 본 파일은 삼신이 사주풀이 플러그인의 **성향(내부 MBTI) 개인화 레이어 계약을 한곳에 모은 단일 소스**입니다.
> `brand.md`가 브랜드 문자열을 중앙화하듯, 이 파일은 성향 레이어의 스키마·분리 규칙·가드·면책을 중앙화합니다.
> SKILL.md·조력자(`agents/*.md`)·대상 메뉴(`menus/01~14`)의 모든 성향 언급은 이 파일의 계약을 따릅니다.
> 성향 레이어를 끄거나 규칙을 바꿀 때는 **이 파일 1곳만** 손보면 전체가 일괄 정합됩니다.
> 상태: **확장 스펙 확정 — 대상 01~14(채용15 제외), 파일럿 3메뉴(07·08·02) 배선 계승.** 3티어 강도 차등(T1 풀/T2 라이트/T3 극소), 10 신살 특례. 상위 참조: `docs/성향결합-확장스펙.md`(§1~§6). 전략팀 종합계획 §6·본 확장 스펙 정합.
> ★표면 표현 규칙(v2 확장): 사용자 출력에는 **"MBTI"·4글자 유형코드를 노출하지 않고 '성향' 언어로만** 전합니다. 내부 데이터(`mbti_profile`·4글자 코드·`source:self_report`)는 그대로 유지합니다(표면만 갈아입음). 축 신호→'성향결' 번역 사전·금지어 하드 가드는 `docs/성향결합-확장스펙.md` §1.

## 0. 한 줄 정체성

성향(내부 MBTI)은 **사주 사실이 아니라 사용자가 스스로 신고한 자기보고 참고값**이며, 삼신이 풀이의 **톤·조언 전달을 개인화하는 데에만** 쓰입니다. 사주팔자·오행·십신·신살·대운은 오직 만세력 엔진 산출 카드에서만 오고, 성향은 그 근거를 한 글자도 건드리지 않습니다.

- **단, 사용자 출력에는 'MBTI'·유형코드를 노출하지 않고 '성향' 언어로만 전한다(내부 데이터는 `mbti_profile` 유지).** 내부에서 4축 신호(E/I·S/N·T/F·J/P)를 읽되, 입 밖으로는 "혼자 곰곰 정리하는 결" "차근차근 계획하는 결" 같은 '성향결' 서술로만 번역해 말한다(번역 사전: `docs/성향결합-확장스펙.md` §1.3).

## 1. 계층 배치 — 엔진 카드와 분리된 제3의 자기보고 레이어

삼신이는 2층 구조입니다: [1층 만세력 엔진 → 결정론 산출 카드] → [2층 AI 해석]. MBTI는 이 **어느 쪽에도 섞이지 않는 제3의 별도 레이어**입니다.

```
[1층 만세력 엔진]  생년월일·시·성별 → saju_engine.py → 산출 카드(JSON)
        │   사주팔자·오행·십신·대운·세운·신살·용신 = 결정론 산출 (사주 사실의 유일 근거)
        │
[별도] MBTI 자기보고 레이어  사용자 입력(선택) → mbti_profile(JSON)  ← 엔진 산출 아님. 사주 사실 근거 아님.
        │   16유형 4글자 코드(E/I·S/N·T/F·J/P) = 사용자가 스스로 신고한 값
        ▼
[2층 AI 해석]  ── 사주 사실 = 엔진 카드 필드값만 근거 ──────────
        │        ── 톤·조언 개인화 = MBTI 레이어 참조(사실 아님) ──
        ▼   삼신이 한 목소리로 감싸 전달 + 면책 2단(+ MBTI 추가 단서)
```

- MBTI 레이어는 엔진 카드(JSON)에 **병합하지 않습니다.** 별도 객체 `mbti_profile`로만 존재합니다.
- MBTI가 엔진 카드 필드값을 덮어쓰거나 보정하는 경로는 **존재하지 않습니다.**

## 2. 스키마 (§6.2 정합 — 엔진 카드와 별도 JSON 객체)

MBTI 프로파일은 엔진 산출 카드와 **별도 JSON 객체**로 관리합니다(엔진 카드에 병합 금지).

```json
{
  "mbti_profile": {
    "provided": true,
    "type": "INTJ",
    "axes": { "EI": "I", "SN": "N", "TF": "T", "JP": "J" },
    "axis_strength": null,
    "source": "self_report",
    "note": "self-reported. NOT a saju fact. tone/advice personalization only."
  }
}
```

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `provided` | MBTI 제공 여부 | `false`이거나 객체 자체가 없으면 → 해석 레이어는 MBTI를 **무시**, 기존 풀이 그대로(강등·오염 없음) |
| `type` | 16유형 4글자 코드 | 대문자 4글자(예: `INTJ`). 유효하지 않으면 `provided:false`로 처리 |
| `axes` | 4축 분해 | EI(E/I)·SN(S/N)·TF(T/F)·JP(J/P). 톤·조언 힌트 도출에 참조 |
| `axis_strength` | 축 강도(슬라이더) | **v2 후보.** MVP는 항상 `null`(4축 코드만) |
| `source` | 출처 | 항상 `self_report` **고정** — 엔진 산출 아님을 스키마 레벨에서 못박음 |
| `note` | 성격 메모 | "사주 사실 아님·톤/조언 개인화 전용"을 스키마 안에 명시 |

- **유효성 판정:** `type`이 16유형(E/I·S/N·T/F·J/P 조합) 중 하나가 아니면 `provided:false`로 강등하고 MBTI를 쓰지 않습니다. 파싱·검증은 엔진과 **무접점**인 별도 유틸(`scripts/mbti_util.py`, 선택)에서 하며, 결정론 엔진(`saju_engine.py`)은 절대 손대지 않습니다.

## 3. 분리 규칙 — 해석 레이어의 MBTI 사용 계약 (§3.2 정합)

### 3.1 MBTI 레이어가 **할 수 있는 것** (톤·조언 개인화만)

- 조언의 **전달 방식** 조정: 계획 선호(J) 신호면 처방을 단계·체크리스트 결로, 즉흥 선호(P) 신호면 "마음 가는 것부터" 결로 표현.
- 위로/축하의 **톤** 조정: 내향(I) 신호면 "혼자 정리할 시간"을 곁들이는 식.
- **어느 조언을 먼저 꺼낼지 우선순위**만 조정.
- **별도 문단으로 도드라지게 전달 가능(강도 상향).** 성향 조언을 네 글자 처방 뒤·면책 앞의 별도 문단("네 성향에 맞춘 삼신이 한마디")으로 모아 도드라지게 할 수 있습니다(문단 템플릿: `docs/성향결합-확장스펙.md` §2). 단 이 문단은 '성향결+맞춤 전달+맞춤 실천'만 담고 사주 사실·앵커 근거(└ 근거)는 담지 않으며, 미제공 시 문단 통째 생략합니다(가드 4). ★10 신살은 별도 문단 없음(§7·확장 스펙 §4.3 특례), ★12 오늘의운세는 초경량 예외(40~80자, 별도 문단 없이 본문 녹임).

핵심: 성향은 이미 엔진 카드로 완성된 해석 골격의 **말투와 순서만** 다듬습니다. 골격의 사주 근거·필드 앵커는 불변입니다.

### 3.2 MBTI 레이어가 **절대 할 수 없는 것** (HARD-LOCK)

- MBTI를 **사주 사실의 근거로 인용 금지.** "네 사주가 이러니 너는 INTJ"(사주→MBTI 도출) 금지. "너는 INTJ니까 사주에 관성이 강하다"(MBTI→사주 위장) 금지.
- MBTI로 **엔진 카드 필드값(오행·십신·신살·대운)을 덮어쓰거나 보정 금지.** 사주 사실은 오직 엔진 카드에서만.
- MBTI를 **과학적 사실로 단정 금지** — "재미·자기이해 참고" 톤 유지. 유형 낙인·고정관념·우열 서술 금지("T라서 공감을 못 한다"류 금지). 유형은 우열이 아니라 결의 차이.
- **네 글자 처방의 '└ 근거'(필드 앵커)는 여전히 엔진 카드 필드만.** MBTI는 처방의 앵커가 될 수 없고, 앵커된 처방의 '말투'만 다듬습니다.

## 4. 4대 가드 (코드/프롬프트 레벨 강제 — §6.3 정합)

MBTI가 사주 근거로 새는 경로를 원천 차단하는 4개 가드입니다. 이 중 하나라도 위반하면 분리 위반이며, 검증 루브릭상 즉시 실패(0점)입니다.

1. **가드 1 — 사주 근거 문장에 MBTI 등장 차단.** MBTI 문자열(유형 코드·축 이름)이 "사주/오행/십신/신살/대운/용신"을 근거로 대는 문장에 등장하면 차단.
2. **가드 2 — 사주→MBTI 도출 차단.** "사주에 따르면 너는 [MBTI]" 패턴 금지(엔진 카드에서 MBTI를 유도하는 경로 자체를 두지 않음).
3. **가드 3 — 처방 근거 줄에 MBTI 앵커 금지.** 네 글자 처방의 "└ 근거" 줄에 MBTI가 앵커로 등장 금지 — 근거는 엔진 카드 필드만.
4. **가드 4 — 미제공 시 언급 금지.** `mbti_profile.provided != true`(또는 객체 부재)이면 성향을 **언급조차 하지 않습니다.** 없는 성향을 짐작·추정해 넣는 것도 금지.
5. **가드 5 — 출력에 유형코드·검사명 노출 금지(표현 전환 하드 가드).** 사용자 출력 어디에도 "MBTI"·"엠비티아이"·"성격유형검사" 등 검사명, "INTJ"·"ENFP" 같은 4글자 유형코드, "E/I·S/N·T/F·J/P" 축 코드, "외향형/내향형" 같은 유형 라벨을 노출하지 않습니다. 내부에서 축을 읽되, 밖으로는 '성향결' 표현으로만 번역합니다(번역 사전: `docs/성향결합-확장스펙.md` §1.3). 한 풀이에서 성향은 가장 도드라지는 1~2축만 짚고, 4축 나열("너는 I·N·T·J") 금지. 유형코드가 사용자 출력에 1건이라도 노출되면 표현 전환 실패입니다.

## 5. 신설 면책 문구 (성향 추가 단서 — §5.1 정합)

대상 메뉴에서 성향을 실제로 반영한 풀이는, 기존 면책 2단(SKILL.md §5.0)의 **2단(정식 면책) 뒤에 아래 추가 단서를** 붙입니다. 기존 공통 면책을 약화하지 않습니다. (유형코드·검사명 없이 '성향'으로 — 오히려 유사과학 리스크가 낮아집니다.)

> 본 풀이에 곁들인 '성향' 이야기는 사용자가 스스로 밝힌 자기 이해를 돕는 참고일 뿐, 과학적 진단이나 확정된 사실이 아닙니다. 성향은 사주 해석의 근거가 아니라, 조언을 더 편히 전하기 위한 참고로만 쓰였습니다. 성향은 우열이 아니라 결의 차이이며, 참고로만 품어 주세요.

- **부착 조건:** `mbti_profile.provided == true`이고 풀이에 성향 톤·조언을 실제로 얹었을 때만 부착합니다(가드 4 정합 — 미제공 시 이 단서도 붙지 않음).
- **부착 위치:** §5.0 2단 정식 면책 원문 뒤. 해당 메뉴에 다른 §5.1 추가 단서(연애·궁합 % 단서 등)가 있으면 그와 함께 나열합니다.

## 6. 데이터 흐름에서의 위치 (§3.3 정합)

1. **입력 수집**(SKILL §2) 단계에서 사주 필수 입력(성별·음양력·생년월일·생시)을 다 받은 **뒤**, 성향(내부 MBTI)을 **선택 입력**으로 가볍게 여쭙니다(삼신이 보이스, SKILL §2.3). 모르면 바로 넘어가고 강등 없습니다. 입력 안내 멘트도 '성향' 언어로 하되, 사용자가 스스로 4글자로 답하면 내부 파싱은 유지합니다(삼신이 출력만 '성향'으로).
2. **엔진 호출**(SKILL §3)로 산출 카드 확보 — 이 단계는 성향과 무관하게 그대로.
3. **내부 조력자 호출**(SKILL §4.0) 시 산출 카드 + (있으면)`mbti_profile`을 함께 넘깁니다. 조력자(만세 할아버지/별이 할멈)는 **카드 필드로 해석 골격을 먼저 완성**한 뒤, `provided==true`면 **처방·조언의 "말투와 우선순위"만** 성향 힌트로 다듬고, 해당 티어면 별도 성향 문단을 세웁니다(T1 풀/T2 라이트/T3 극소·10 특례).
4. **삼신이가 감싸 전달** + 면책 2단(+ §5 성향 추가 단서). 사용자 출력에는 유형코드·검사명을 노출하지 않고 '성향결'로만 번역해 말합니다(가드 5).

## 7. 대상 범위·확장 (14메뉴 3티어 차등 · 확장 스펙 §4 정합)

- **대상: 01~14 (14개 메뉴).** 파일럿 3개(07·08·02) 배선을 계승해 14메뉴로 일관 확장합니다. 성향 반영 강도는 아래 3티어로 차등합니다.
- **3티어 강도 체계(상세: `docs/성향결합-확장스펙.md` §4.1):**
  - **T1 풀 적용** — 성향결+맞춤 조언+실천 별도 문단 풀세트. 대상: **01·02·03·06·07·08·13·14**(그룹 A 실용).
  - **T2 라이트** — 성향을 '마음가짐·다스리는 결'에만 1~2문장, 서사 안 깨게(축소 문단 또는 본문 녹임). 대상: **04·05·09·11**(그룹 B 서사).
  - **T3 극소/안전 특례** — 별도 문단 없음, 본문 녹임. 대상: **10 신살(특례 하드 가드)·12 오늘의운세(초경량)**.
- **★10 신살풀이 특례(낙인 리스크 최상 · 확장 스펙 §4.3):** ① 신살↔성향 연결 문장 전면 금지("네 성향이 OO라 이 살이…"·"이 살이 있어 네 성향이…" 어떤 방향도 금지 — 신살 서술과 성향 서술을 한 문장·한 문단에 두지 않음) ② 성향은 오직 '살을 다스리는 법' 처방의 말투에만 극소 ③ 별도 성향 문단 없음 ④ 미제공·순화 우선(순화 3원칙이 성향보다 항상 우선). 못 지킬 바엔 10은 성향 미적용(생략)이 안전 기본값.
- **그룹 B 공통 안전(04·05·09·10·11):** 서사·묘사 구간엔 성향 0 — 성향은 항상 맺음·다스리는 법·마음가짐 구간에만. 미제공 시 전원 생략. 순화·공포 금지가 성향보다 우선.
- **채용참고(15)는 원칙적 제외.** 성향(MBTI) 기반 유형 스크리닝은 채용 차별 위험을 가중하므로 이번 확장·성향 결합 대상이 아닙니다(§4.3 원칙). 이 예외는 담당자님·법무 승인 없이 열지 않습니다.
- **12(오늘의운세)는 짧고 가벼운 정체성 유지.** 표현 전환(성향 언어)만 적용하고, 성향 반영도 '오늘 한 가지' 행동의 말투 결에만 40~80자로 녹입니다. 분량 상향·별도 문단 풀세트 금지(가벼움이 정체성).

## 8. 거버넌스 위반 0 확인 문장

> 본 계약은 삼신이 SKILL.md §0(엔진 산출만이 사주 근거) 위반 0, §4.3(깊이·처방·중대결정 안전장치) 정합, §5(면책 2단 강제) 위반 0, §7.5(단일 창구·새 user-facing 스킬 금지·페르소나 일관) 위반 0을 만족한다. 이번 확장은 (1) 표면 언어를 '성향'으로 바꾸고 (2) 성향 조언을 별도 문단으로 도드라지게 하며 (3) 일상 예시·처방 밀도로 상세화할 뿐, 분리 계약의 실체는 한 글자도 바꾸지 않는다. 성향(내부 `mbti_profile`)은 엔진 산출 카드와 물리적으로 분리된 자기보고 입력 레이어로만 존재하고, 사주 사실 근거로는 절대 쓰이지 않으며 오직 2층 해석의 톤·조언 개인화 힌트로만 참조된다. **유형코드·검사명을 사용자에게 노출하지 않음으로써 오히려 유사과학 단정 리스크가 낮아진다.** 성향은 새로운 user-facing 스킬이 아니라 삼신이(saju-reading)가 내부에서 참조하는 모듈이며, 사용자 대면 화자는 여전히 삼신이 하나다. 엔진 카드 필드값을 성향이 덮어쓰거나 보정하는 경로는 존재하지 않는다. 채용참고(15)는 차별 리스크로 성향 결합 대상에서 계속 제외된다.
