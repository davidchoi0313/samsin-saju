# 선택 성향 레이어 계약

이 문서는 사용자가 성향 유형을 자발적으로 제공했을 때만 읽는다. 성향 정보는 사주 계산과 완전히 분리하며, 조언의 전달 방식과 실행 순서를 조금 더 편하게 조정하는 데만 쓴다.

## 1. 기본 원칙

- 성향은 사용자의 자기보고 참고값이다. 사주 사실, 의학적 진단, 과학적으로 확정된 성격이 아니다.
- 성향을 받지 않았으면 추정하거나 다시 묻지 않는다. 성향 관련 문장과 면책도 모두 생략한다.
- 성향 때문에 사주 카드의 값이나 해석을 바꾸지 않는다.
- 고객이 직접 말한 생활 경험이 성향 설명과 다르면 고객의 경험을 우선한다.
- 채용 참고(M15)에는 성향 정보를 사용하지 않는다.

## 2. 내부 데이터

사주 카드에 병합하지 않고 아래 별도 객체로만 관리한다.

```json
{
  "mbti_profile": {
    "provided": true,
    "type": "INTJ",
    "axes": { "EI": "I", "SN": "N", "TF": "T", "JP": "J" },
    "axis_strength": null,
    "source": "self_report",
    "note": "self-reported; advice-delivery hint only; not a saju fact"
  }
}
```

- `type`이 E/I·S/N·T/F·J/P의 유효한 네 글자 조합이 아니면 `provided:false`로 처리한다.
- `source`는 항상 `self_report`다.
- 사주 엔진에는 이 객체를 넘기지 않는다.

## 3. 허용되는 사용

성향은 이미 완성된 사주 해석의 **근거나 행동 주제를 바꾸지 않고, 실행 방법**을 조정한다. 사주 카드가 `무엇을 관찰하고 시험할지` 정하면 성향은 그 실험을 글·대화·계획·선택지 중 어떤 형태로 해야 고객이 옮기기 편할지 정한다. 구체 행동은 `action-library.md`의 안전선과 완료 기준을 따른다.

- 단계적인 방식을 편하게 여기는 사람에게는 `1단계 → 2단계 → 확인 기준` 순서로 제안한다.
- 선택의 여지를 편하게 여기는 사람에게는 두세 가지 중 하나를 고르는 방식으로 제안한다.
- 혼자 정리하는 시간을 선호한다고 스스로 밝혔다면, 대화 전에 메모하는 행동을 앞에 둔다.
- 대화하며 생각을 정리하는 편이라고 스스로 밝혔다면, 짧은 질문이나 말로 정리하는 행동을 앞에 둔다.
- 계획을 편하게 여기는 사람에게는 날짜·반복 횟수·완료 기준을 먼저 고정하고, 유연한 선택을 편하게 여기는 사람에게는 두 방법을 짧게 시험한 뒤 고르게 한다.

이 조정도 고정관념이 아니라 선택지로 말한다. `이 방식이 더 편하다면`, `둘 중 맞는 쪽을 골라`처럼 고객이 다르게 느낄 여지를 둔다.

성향 정보가 없으면 개인화를 포기하지 않는다. 사주 계산으로 행동의 주제를 정한 뒤 `글로 먼저 정리하기 / 말로 먼저 풀어보기`처럼 실행 방식 두 개를 짧게 제시하고 고객이 고르게 할 수 있다. 성향 유형을 추정해서 한쪽을 대신 선택하지 않는다.

## 4. 금지되는 사용

- `사주를 보니 이런 유형이다`처럼 사주에서 성향 유형을 도출하지 않는다.
- `이 유형이라 관성이 강하다`처럼 성향을 사주 근거로 쓰지 않는다.
- 궁합·성공률·건강·재물·직업 적합도·채용 판단을 만들지 않는다.
- `이 유형은 공감이 부족하다`, `저 유형과 맞지 않는다`처럼 낙인찍지 않는다.
- 사용자 출력에 검사명, 네 글자 유형 코드, 축 코드, 내부 객체명을 노출하지 않는다.
- 성향만 따로 길게 해설하거나 사주 본문을 반복하지 않는다.

## 5. 고객에게 보이는 표현

한 풀이에서 가장 관련 있는 성향 단서 한두 개만 생활어로 바꿔 쓴다.

| 내부 힌트 | 자연스러운 표현 예시 |
|---|---|
| 혼자 정리 선호 | 혼자 생각을 정리한 뒤 말할 때 더 편할 수 있어. |
| 대화하며 정리 선호 | 누군가와 짧게 이야기하며 생각을 잡는 편이 더 편할 수 있어. |
| 구체 정보 선호 | 사례와 숫자를 먼저 확인하는 방식이 잘 맞을 수 있어. |
| 큰 그림 선호 | 전체 방향을 먼저 잡고 세부로 내려오는 방식이 편할 수 있어. |
| 논리 기준 선호 | 판단 기준을 글로 적어 비교하면 결정을 정리하기 쉬울 수 있어. |
| 관계 영향 고려 | 결정이 사람에게 미칠 영향을 한 번 더 살피는 방식이 편할 수 있어. |
| 계획 선호 | 시작 시점과 완료 기준을 먼저 정하면 실행하기 수월할 수 있어. |
| 유연한 선택 선호 | 선택지 두 개를 열어두고 먼저 해본 뒤 정하는 방식이 편할 수 있어. |

`결`, `기운`, `타고났다` 같은 말로 성향을 포장하지 않는다. 위 문장은 모두 `그럴 수 있어`라는 선택 가능한 표현으로 쓴다.

## 6. 메뉴별 강도

- 01·02·03·06·07·08·13·14: 실행 카드의 순서나 표현에 한두 문장 반영할 수 있다.
- 04·05·09·11: 상징 서사에는 넣지 않고 맺음말이나 행동 제안에 한 문장만 반영한다.
- 10: 신살과 성향을 같은 문장이나 인과관계로 엮지 않는다. 안전하게 분리하기 어렵다면 생략한다.
- 12: 오늘 행동의 전달 방식에 한 문장 이내로만 반영한다.
- 15: 사용하지 않는다.

## 7. 고정 추가 단서

`mbti_profile.provided == true`이고 실제 출력에 성향을 반영했을 때만 공통 면책 앞에 아래 문구를 그대로 붙인다.

> 본 풀이에 곁들인 성향 이야기는 사용자가 스스로 밝힌 자기이해 참고값입니다. 사주 해석의 근거나 과학적 진단이 아니며, 조언을 편하게 전하기 위한 참고로만 사용했습니다.

공통 면책은 `output-contract.md`의 원문을 그대로 이어 붙인다.

## 8. 출력 전 확인

- 성향을 사주 계산의 근거처럼 쓰지 않았는가?
- 검사명·유형 코드·축 코드가 고객 문장에 남지 않았는가?
- 제공하지 않은 성향을 추정하지 않았는가?
- 성향 설명이 사주 본문을 반복하지 않는가?
- 행동 제안이 실제로 더 이해하기 쉬워졌는가?
