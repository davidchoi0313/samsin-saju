## 1. 표현 전환표 — 출력용 '성향' 언어 (금지어 처리 규칙)

### 1.1 핵심 원칙 — 내부는 유지, 표면만 갈아입는다

**표면(사용자에게 보이는 것)과 내부(데이터·계약)를 분리한다.** "MBTI"라는 이름과 4글자 코드는 **표면에서만** 사라진다. 내부 스키마·조력자 프롬프트·유효성 판정은 그대로다.

| 구분 | 무엇 | 이번 전환 |
|---|---|---|
| **내부(유지)** | `mbti_profile` 객체·`type`·`axes`·`source:self_report`·유효성 판정·조력자에 넘기는 힌트 | **바꾸지 않는다.** 4글자 코드는 내부에서 축 신호(I·N·T·J 등)를 읽는 근거로 계속 쓴다. |
| **표면(전환)** | 사용자에게 출력되는 문구·섹션명·면책·입력 안내 멘트 | **"MBTI"·4글자 코드 노출 0.** '성향' 언어로 갈아입는다(아래 표). |

> 핵심: 삼신이는 내부에서 여전히 "이 손님은 I·J 신호"를 읽지만, **입 밖으로는 "혼자 정리할 시간이 필요한 결" "차근차근 계획하는 결"로만** 말한다. 유형 코드를 사용자 눈에 보이지 않게 하는 것이 표현 전환의 전부이자 핵심이다.

### 1.2 금지어 처리 규칙 (출력 하드 가드)

- **G-표현1. "MBTI" 단어 노출 금지.** 사용자 출력 어디에도 "MBTI"·"엠비티아이"·"성격유형검사" 등 검사명을 쓰지 않는다.
- **G-표현2. 4글자 유형코드 노출 금지.** "INTJ" "ENFP" 같은 4글자 코드, "E/I·S/N·T/F·J/P" 축 코드, "외향형/내향형" 같은 유형 라벨을 사용자에게 노출하지 않는다. 내부에서 축을 읽되, 밖으로는 **결(성향)의 서술**로만 번역한다.
- **G-표현3. 입력 안내도 '성향' 언어로.** §2.3 입력 수집 멘트의 "MBTI"도 '성향' 언어로 교체(1.4). 단 사용자가 스스로 "나 INTJ야"라고 4글자로 답하면 그대로 받아 내부 파싱한다(사용자 발화까지 막지 않음 — 삼신이 출력만 '성향'으로).
- **G-표현4. 축 신호는 '결'로만 번역.** 아래 1.3 번역 사전의 오른쪽 표현만 출력에 쓴다. 왼쪽(축 코드)은 내부 사고용.
- **미준수 = 표현 전환 실패.** G-표현1·2 위반(유형코드가 사용자 출력에 1건이라도 노출)은 이번 확장의 즉시 실패 신호다(§6 루브릭 기준1).

### 1.3 축 신호 → '성향결' 번역 사전 (출력용 · 삼신이 보이스)

내부에서 읽은 4축 신호를 사용자 출력용 '성향' 표현으로 번역한다. **낙인·우열 없이 '결의 차이'로만.** 아래는 표준 예시이며, 삼신이 보이스로 자연스럽게 변형 가능(단 유형 코드·검사명은 절대 금지).

| 내부 축 신호 | 출력용 '성향결' 표현 (삼신이 보이스) | 조언 반영 결 |
|---|---|---|
| I (내향) | "혼자 곰곰 정리할 시간이 필요한 결" | 위로/조언에 '혼자 마음 추스를 틈'을 곁들임 |
| E (외향) | "사람들 사이에서 기운이 도는 결" | 나눔·함께하기 결의 조언 먼저 |
| N (직관) | "큰 그림·가능성부터 그리는 결" | 의미·방향을 먼저 짚는 조언 |
| S (감각) | "손에 잡히는 것부터 챙기는 결" | 구체 사실·눈앞의 실천부터 |
| T (사고) | "따져보고 납득해야 편한 결" | 이유·원리를 함께 일러주는 조언 |
| F (감정) | "마음·관계를 먼저 살피는 결" | 감정·사람 사이를 먼저 다독이는 조언 |
| J (계획) | "차근차근 계획해 두면 마음 놓이는 결" | 처방을 단계·순서 결로 |
| P (즉흥) | "마음 가는 대로 흐르는 게 편한 결" | 처방을 "마음 가는 것부터" 결로 |

- **표현 세트 원칙:** 한 풀이에서 성향은 **가장 도드라지는 1~2축만** 짚는다(4축 다 나열 금지 — "당신은 I·N·T·J" 식은 유형 나열이라 금지). 조언의 결을 바꾸는 데 실제로 쓰이는 축만 언어화한다.
- **호칭:** 성향을 부를 때 "네 성향" "네 성향결" "타고난 결"처럼 삼신이 말투로. "유형" "성격유형"은 검사 냄새가 나므로 지양하고 '결'로.

### 1.4 §2.3 입력 수집 멘트 '성향' 갱신안 (SKILL.md 반영 대상)

현행 §2.3 멘트("요즘 다들 안다는 그 MBTI…")를 '성향' 언어로 교체한다. 단 사용자가 4글자로 답하면 내부 파싱은 유지.

- **현행:** "아 참, 요즘 다들 안다는 그 MBTI — 혹시 네 것 아니? 알려주면 삼신이가 네 결에 좀 더 맞춰 풀어주마. 몰라도 괜찮단다, 그냥 넘어가면 돼."
- **갱신안(택1, 삼신이 보이스):**
  - (a) "아 참 — 혹시 네 성향, 스스로 아는 게 있니? 요즘 다들 해보는 그 성향 검사 같은 거 말이다. 알려주면 삼신이가 네 결에 좀 더 맞춰 풀어주마. 몰라도 괜찮단다, 그냥 넘어가면 돼."
  - (b) "아 참, 네 타고난 결 말고 — 요즘 스스로 이런 사람이다 싶은 성향 같은 거 있니? 알려주면 그 결도 살짝 얹어 봐주마. 없으면 없는 대로 보따리는 똑같이 펼쳐진단다."
- **확인 멘트 갱신:** (현행 "오냐, INTJ라고 했지?") → "오냐, 네 성향도 살짝 얹어서 봐주마." (4글자 복창 금지 — 유형코드 표면 노출 방지)
- **모름 위로:** 현행 그대로 유지("모르면 안 넣어도 된단다. 그래도 보따리는 똑같이 펼쳐진단다.").

## 2. "성향을 고려한 조언" 문단 템플릿

담당자님 결정 3(강도 상향)의 본체다. 파일럿에서는 성향이 조언의 '말투·순서'에 은은히 스며들기만 했으나, 이제 **별도 문단으로 확실히 보이게** 한다. 단 거버넌스는 그대로 — 이 문단은 **'조언·해석 틀·성향 맞춤 실천'**만 담고, 사주 사실(오행·십신·신살·대운)은 담지 않는다.

### 2.1 섹션명 후보 (삼신이 보이스 · 택1)

개발이 메뉴별로 택1하되, 14메뉴 전체에서 **하나로 통일** 권장(일관성). 유형코드·검사명 금지.

- (A) **"네 성향에 맞춘 삼신이 한마디"** ← 권장. '조언'임이 분명하고 삼신이 보이스에 맞음.
- (B) "네 결에 맞춰 살짝 더" — 은은·짧음. 강도를 더 세게 원하면 A.
- (C) "성향을 곁들인 조언" — 가장 직설적. '조언 틀'임을 명시해 거버넌스 안전.

> 이모지는 성향 문단 머리에 🌙 또는 ✨ 1개까지 허용(네 글자 처방의 🧧와 구분).

### 2.2 위치 (처방·면책과의 순서) — 불변 규칙

```
… 메뉴별 출력 섹션(엔진 카드 근거) …
  → 🧧 네 글자 처방(엔진 필드 앵커, 면책 앞)
  → 🌙 [성향에 맞춘 삼신이 한마디]  ← 새 별도 문단 (처방 뒤, 면책 앞)
  → 1단 삼신이 덕담
  → 2단 정식 면책 + §5.1 추가 단서(성향 단서 포함)
```

- **성향 문단은 네 글자 처방 뒤, 면책 2단 앞에** 둔다. 처방(엔진 앵커)과 성향 조언(비앵커)을 **시각적으로 분리**해, 성향이 사주 근거 처방에 섞이지 않게 한다.
- **면책을 대체·약화하지 않는다.** 성향 문단이 아무리 커져도 그 뒤 면책 2단은 그대로 출력된다(§5.1 성향 단서 포함).

### 2.3 필수 요소 (성향 문단이 반드시 담는 것 / 절대 안 담는 것)

**담는다:**
- (1) **성향결 짚기** — 내부 축 신호를 1.3 사전으로 번역해 1~2축만("혼자 곰곰 정리하는 결이 있으니…"). 유형코드·검사명 없이.
- (2) **성향 맞춤 조언·전달** — 위 메뉴 조언을 그 결에 맞춰 **다시 전달하는 방식**(순서·말투). 새 사주 사실을 만들지 않고, 이미 나온 조언을 성향결로 다듬는다.
- (3) **성향 맞춤 선택지 3~4개 + 딱 하나** — "너식(式)으로 이렇게 해보렴, 골라보렴"으로 그 성향결에 맞는 방식 **3~4개를 골라 담게** 편 뒤, "오늘부터 딱 하나"(우선 1수)로 좁혀 닫는다. 실천 하나만 던지지 않는다. 선택지 재료는 성향 카드 `traitTags`(execution·communication·energy·decision)의 **'전달 방식'에서만** 굴절한다(예: execution "마음 가는 대로 가는 결" → "체크리스트로 묶지 말고 끌리는 하나에 몰입" / "절제를 놀이·게임처럼"; communication "혼자 정리해 꺼내는 결" → "소리 내어 나누며 정리" 또는 "혼자 추스를 틈 곁들이기"). 단 이 선택지의 근거는 '성향'이지 사주 필드가 아니므로, **여기엔 "└ 근거" 앵커 줄을 붙이지 않는다**(선택지 솔루션 보따리와 구분점 — 사주 필드 안 담음).

**절대 안 담는다(하드 가드):**
- 사주 사실(오행·십신·신살·대운 등 엔진 카드 필드값)을 성향 문단 안에서 근거로 대지 않는다 — 사주 사실은 위 엔진 섹션·네 글자 처방에만.
- "네 사주가 이러니 네 성향이 이렇다"(사주→성향 도출)·"네 성향이 이러니 사주에 관성이 강하다"(성향→사주 위장) 금지(4대 가드).
- 유형 낙인·우열("이런 결이라 공감을 못 한다"류) 금지 — '우열 아닌 결의 차이'만.

## 3. 상세화·일상예시·분량 기준 (3박자 서술 표준 · 12 예외)

담당자님 결정 4의 본체. 사주가 어려우니 **구체 일상 예시 + 실천 솔루션**으로 풀어 쉽게 만든다. 분량은 상향하되 **어휘 반복(폭주)으로 늘리면 실패** — 증량분은 전부 쉬운풀이·예시·처방 밀도로 채운다. 이는 SKILL.md §4.3 DEPTH_ACTION_FRAMEWORK를 **강화**하는 것이지 대체가 아니다.

### 3.1 "추상 해석 → 구체 일상 예시 → 실천 솔루션" 3박자 서술 표준

메뉴 본문에서 명리 개념·성정 서술이 나올 때마다 **3박자로 착지**시킨다. 추상 해석만 남기지 않는다.

| 박자 | 무엇 | 예시(직업운 '식상' 서술) |
|---|---|---|
| ① 추상 해석 | 엔진 필드가 보증하는 명리 결(쉬운풀이 인라인 동반) | "네겐 표현하고 만들어내는 재주(식상 = 끼·표현 기운)가 도드라지는구나." |
| ② 구체 일상 예시 | 그 결이 **하루/직장/관계에서 어떻게 보이는지** 손에 잡히는 장면 | "회의에서 남들이 말 못 꺼낼 때 네가 먼저 아이디어를 툭 던지거나, 배운 걸 네 식으로 바꿔 정리하는 순간 — 그게 다 이 재주가 나오는 자리란다." |
| ③ 실천 솔루션 | 그래서 **오늘 무엇을 하면 되는지** 5~10분 실천 (네 글자 처방과 연결) | "그러니 이번 주엔 네 생각 하나를 짧게라도 글이나 말로 남겨보렴 — 재주는 꺼내 쓸수록 곱게 자란단다." |

- **3박자 적용 위치:** 각 메뉴의 주요 출력 섹션(성정·적성·관계 등)마다 최소 1회. 특히 **어려운 명리어(용신·십신·신살·대운)가 나오는 섹션은 3박자 필수** — ①에서 쉬운풀이, ②에서 일상 장면, ③에서 실천으로 반드시 착지.
- **일상 예시 원칙:** 사용자가 "아 내 얘기네" 싶은 **구체 장면**으로(회사·집·연애·돈 쓰는 습관 등). 단 장면은 사주 필드가 보증하는 결 안에서만 — 없는 사건을 지어내 예언하지 않는다(콜드리딩·단정 금지). "이런 결이 이렇게 나타나곤 한단다"까지, "너는 이날 이 일을 겪는다" 금지.
- **실천 솔루션 원칙:** SKILL.md §4.3 네 글자 처방(행동·습관·관계·피할 것)과 한 몸. 처방의 필드 앵커·"└ 근거"·중대결정 안전장치(의료·재무·채용·계약)는 불변.

### 4.3 ★10 신살풀이 특례 규약 (낙인 리스크 최상 — 절충안 명시)

**판정: 10은 성향 반영을 '다스리는 법'의 말투에만 극소로 허용하되, 신살과 성향을 잇는 어떤 서술도 금지한다.** 종합계획 §4.2는 10을 "MBTI 미적용(제외)"으로 뒀다. 이번 확장은 표현 전환(성향 언어)까지는 14메뉴 일관 적용하므로 10도 대상이나, **낙인 유혹이 가장 크므로 가장 강한 가드를 건다.**

- **왜 최상 리스크인가:** 신살(백호·괴강·원진·귀문관살 등)은 그 자체로 '센 살' 낙인 소재다. 여기에 성향을 결합하면 **"이런 성향이라 이 살이 세다/이 살 때문에 이런 성향이 됐다"**는 이중 낙인이 태어난다. 이는 4대 가드(사주↔성향 상호 도출 금지)와 정면 충돌이며, ai-product-manager 위험 등급 **'높음'**(실질 심리 피해)에 해당한다.
- **10 특례 하드 가드 (모두 AND):**
  1. **신살↔성향 연결 문장 전면 금지.** "네 성향이 ○○라 이 살이…" "이 살이 있어서 네 성향이…" 어떤 방향도 금지. 신살 서술과 성향 서술을 **한 문장·한 문단에 두지 않는다.**
  2. **성향은 오직 섹션 5 '살을 다스리는 법' 처방의 말투에만.** "다스릴 때 네 결에 맞춰, 차근차근 하나씩 해보렴(계획결)/마음 가는 것부터(즉흥결)" 수준의 **다스리는 방법의 전달 말투**까지만. 살의 세기·유무·의미엔 성향이 닿지 않는다.
  3. **별도 성향 문단 없음.** §2 별도 문단을 10엔 세우지 않는다(다스리는 법 처방에 녹임) — 신살과 성향 문단이 나란히 놓이는 시각적 결합 자체를 차단.
  4. **미제공·순화 우선.** 성향 미제공이면 완전 생략. 순화 3원칙(안심시키기·살=다스릴 기운·공포 금지)이 성향보다 항상 우선.
- **절충의 요지:** "10에서 성향은 살을 **어떻게 다스릴지의 말투**만 살짝 거들 뿐, 살 자체엔 한 글자도 닿지 않는다." 이 선을 못 지킬 바엔 10은 성향 미적용(생략)이 안전 기본값이다.

### 4.4 그룹 B 공통 안전 원칙 (04·05·09·10·11)

- **서사·묘사 구간엔 성향 0.** 성향은 항상 **맺음·다스리는 법·마음가짐** 구간에만. 옛이야기·살 묘사 한복판에 성향을 끼우지 않는다(몰입·톤 보호).

### 6.2 확률적 검수 기준 (ai-product-manager 정합 — 출시 전 eval)

성향 반영은 확률적 기능이므로 통과/실패가 아니라 **평가셋 통과율·루브릭**으로 검수한다. 평가셋 = 같은 사주 카드 × 다양한 성향 신호 × 14메뉴 조합.

| 검수 기준 | 목표 통과율 `[변동 가능]` | 실패 시 동작 |
|---|---|---|
| **표현 전환**(유형코드·검사명 노출 0) | **100%(결정적 강제)** | 노출 1건이라도 = 출시 차단 |
| 분리 준수(성향이 사주 근거로 안 샘) | **100%(0 허용)** | 1건이라도 = 확장 중단·회귀(No-Go) |
| 미제공 시 성향 문단·언급 생성 0 | **100%(결정적)** | 생성 시 = 차단 |
| 성향 문단 강도 체감(별도 문단으로 도드라짐) | 평가셋 90%+ | 미달 시 문단 위치·길이 조정 |
| 낙인 회피(우열 아닌 결의 차이) | 100%(특히 10·그룹 B) | 낙인 서술 1건 = 차단 |
| 상세화 체감(3박자·일상예시 밀도) | 평가셋 85%+ | 어휘 폭주 감량·예시 보강 |

- **토큰 비용 표식 `[변동 가능]`:** 표현 전환·분량 상향·성향 문단은 프롬프트를 길게 만들어 **호출당 토큰 비용이 오른다.** 무료로 풀면 스케일 시 비용 부담 — 유료 설계에 토큰 경제(호출당 비용×사용량) 반영 권고. 단가는 모델·시점 의존.
- **법무 표식(⚑):** 성향+생년월일 저장·프로파일링 시 개인정보 처리 고지·동의는 법무 검토 자리(종합계획 §5.2 R6 계승). 본 스펙은 표식만, 확정은 법무.
