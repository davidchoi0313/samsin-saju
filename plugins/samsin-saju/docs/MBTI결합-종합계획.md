## 0. 30초 핵심 (결정 먼저)

- **이 계획의 척추는 "가설 검증"입니다.** 담당자님의 프레이밍("MBTI를 결합하면 더 개인화된 솔루션이 나오지 않을까")은 아직 **검증되지 않은 가설**이며, 이 문서는 그 가설을 값싸게·빠르게 검증한 뒤 확장하도록 설계됐습니다.
- **추천 결합안: (A) 전 메뉴 개인화 레이어** — 단 파일럿 3개 메뉴로 좁혀 시작. (B 신규 전용 메뉴)는 §7.5 단일창구·확장 규칙과 정면 충돌하므로 기각, (C 둘 다)는 가설 미검증 상태의 과투자로 보류.
- **아키텍처 급소 준수:** MBTI는 만세력 엔진 카드와 **분리된 '자기보고 입력 레이어'**로만 태우고, 해석 레이어에서 **톤·조언 개인화에만** 쓰며 **사주 사실 근거로는 절대 쓰지 않습니다.** "엔진-우선·단일창구 위반 0"을 §3에서 문장으로 확인.
- **시장 근거(실데이터):** MBTI×사주 결합은 이미 실재하는 트렌드입니다(포춘토리 2025-09, '운이온다' 2026-06 등). 삼신이의 차별점은 결합 자체가 아니라 **엔진-우선 결정론 + 캐릭터 페르소나 + 분리 가드**라는 구조에 있습니다(§7).

## 1. 가설 정의 + 검증 설계

### 1.1 가설을 검증 가능한 형태로 재정의

담당자님 원 가설(느슨한 형태): "요즘 대부분 자기 MBTI를 아니까, MBTI를 결합하면 더 개인화된 솔루션이 나오지 않을까."

검증 가능한 형태로 조작화(operationalize):

> **H1 (개인화 체감).** 같은 사주 입력에 대해, MBTI를 결합한 풀이는 MBTI 없는 풀이보다 사용자의 '나에게 맞춘 느낌(개인화 체감)'을 유의하게 높인다.
> **H2 (상품성·유지).** MBTI 결합 풀이를 받은 사용자는 그렇지 않은 사용자보다 재방문·추가 메뉴 이용·공유 의향이 높다.

이 가설은 **AI 기능이므로 결정적 '통과/실패'가 아니라 확률적으로** 검증합니다(같은 사주여도 MBTI가 다르면 출력이 달라지고, 같은 MBTI여도 표현이 매번 조금씩 다름). 따라서 인수조건은 통과율·정도로 잡습니다(§3.1 확률적 인수조건 계보).

### 1.2 측정 지표 (2개 이상 — 완성 기준 충족)

| 지표 | 정의 | 측정 방법 | 대상 가설 |
|---|---|---|---|
| **M1 개인화 체감 점수** | 풀이 직후 "이 풀이가 나에게 맞춘 느낌이었다" 5점 리커트 | 풀이 끝 1문항 마이크로 서베이(삼신이 보이스로 가볍게) | H1 |
| **M2 내부 개인화 루브릭 점수** | 풀이 텍스트가 MBTI 신호를 톤·조언에 실제로 반영했는지 0~2점×5기준 채점 | 내부 평가셋 채점(사람+AI 채점, §1.4) | H1 |
| **M3 재방문·추가이용률** | 첫 풀이 후 N일 내 재방문 또는 추가 메뉴 이용 비율 | 세션 로그(익명 집계) | H2 |
| **M4 공유/저장 의향** | "이 결과 친구에게 보여주고 싶다" 응답 비율 | 마이크로 서베이 선택 문항 | H2 |

> 최소 필수는 M1(체감)·M2(루브릭) 2개. M3·M4는 상품성 확장 근거로 병행 권장.

### 1.3 검증 방법 — MBTI 있음/없음 A/B

- **설계:** 동일 사용자군을 두 갈래로. **대조군(MBTI 미수집)** vs **실험군(MBTI 수집·반영)**. 같은 메뉴(파일럿 3개)에서 M1~M4 비교.
- **주의(교란 통제):** 두 군의 사주 엔진 산출은 동일해야 함(개인화 차이가 오직 MBTI 레이어에서만 오도록). 텍스트 길이·이모지 등 표면 변수도 통제.
- **표본:** 통계적으로 충분한 수(내부 파일럿은 정성 피드백 20~30건 + M2 평가셋 100건부터 시작, 정량 A/B는 트래픽 확보 후) `[추정 — 표본 수는 실트래픽 규모에 따라 조정]`.

### 1.4 내부 개인화 루브릭 (M2 채점 기준 — 확률적)

평가셋(같은 사주 카드 × 다양한 MBTI 16종 조합, 최소 100케이스)을 만들어 아래 5기준을 0~2점 채점:

1. **반영성** — MBTI 신호가 톤/조언에 실제로 드러났나(단순 "당신은 INTJ" 나열이 아니라 조언의 결이 바뀌었나)
2. **분리 준수** — MBTI를 사주 사실 근거로 오용하지 않았나(가장 중요, 0점이면 즉시 실패)
3. **페르소나 일관** — 삼신이 한 목소리 유지, 심리검사관 말투로 튀지 않았나
4. **낙인 회피** — 유형을 고정관념·우열로 서술하지 않았나
5. **면책 유지** — MBTI를 과학적 사실로 단정하지 않고 면책 2단 보존했나

### 1.5 최소 성공 기준 (Go/No-Go)

- **M1:** 실험군 개인화 체감 평균이 대조군보다 유의하게 높음(방향성 + 정성 코멘트에서 "더 나에게 맞다" 우세) `[변동 가능 — 임계값은 파일럿 표본으로 확정]`
- **M2:** 루브릭 평균 **기준2(분리 준수) 100케이스 중 100건 통과(0 허용)**, 나머지 4기준 평균 1.4/2.0 이상 `[변동 가능]`
- **No-Go 신호:** 분리 준수 위반이 1건이라도 발생하면(MBTI가 사주 근거로 샘) 확장 중단·설계 회귀. 개인화 체감 차이가 무의미하면 결합 가치 재검토.

## 3. 아키텍처 결정 (설계 급소 준수)

### 3.1 계층 배치 — MBTI는 엔진 카드와 분리된 자기보고 레이어

삼신이는 2층 구조입니다: [1층 만세력 엔진 → 결정론 산출 카드] → [2층 AI 해석]. MBTI는 이 **어느 쪽에도 섞이지 않는 제3의 별도 레이어**로 둡니다.

```
[1층 만세력 엔진]  생년월일·시·성별 → saju_engine.py → 산출 카드(JSON)
        │   사주팔자·오행·십신·대운·신살·용신 = 결정론 산출 (사주 사실의 유일 근거)
        │
[별도] MBTI 자기보고 레이어  사용자 입력(선택) → mbti_profile(JSON)  ← 엔진 산출 아님. 사주 사실 근거 아님.
        │   16유형 코드 + (선택)4축 강도 = 사용자가 스스로 신고한 값
        ▼
[2층 AI 해석]  ── 사주 사실 = 엔진 카드 필드값만 근거 ──────────
        │        ── 톤·조언 개인화 = MBTI 레이어 참조(사실 아님) ──
        ▼   삼신이 한 목소리로 감싸 전달 + 면책 2단
```

### 3.2 분리 규칙 (해석 레이어의 MBTI 사용 계약)

**MBTI 레이어가 할 수 있는 것(톤·조언 개인화만):**
- 조언의 **전달 방식** 조정: 예) 계획 선호(J) 신호면 처방을 단계·체크리스트 결로, 즉흥 선호(P) 신호면 "마음 가는 것부터" 결로 표현.
- 위로/축하의 **톤** 조정: 내향(I) 신호면 "혼자 정리할 시간"을 곁들이는 식.
- **어느 조언을 먼저 꺼낼지 우선순위**만 조정.

**MBTI 레이어가 절대 할 수 없는 것(HARD-LOCK):**
- MBTI를 **사주 사실의 근거로 인용 금지.** "네 사주가 이러니 너는 INTJ"(사주→MBTI 도출) 금지. "너는 INTJ니까 사주에 관성이 강하다"(MBTI→사주 위장) 금지.
- MBTI로 **엔진 카드 필드값을 덮어쓰거나 보정 금지.** 오행·십신·신살·대운은 오직 엔진 카드에서만.
- MBTI를 **과학적 사실로 단정 금지** — "재미·자기이해 참고" 톤 유지, 유형 낙인·고정관념 금지(§5).
- **네 글자 처방의 '필드 앵커'는 여전히 엔진 카드 필드만.** MBTI는 처방의 앵커가 될 수 없고, 앵커된 처방의 '말투'만 다듬는다.

### 3.3 데이터 흐름에서의 위치

1. 입력 수집(§2 SKILL) 단계에서 사주 필수 입력을 다 받은 **뒤**, MBTI를 **선택 입력**으로 가볍게 여쭘(삼신이 보이스, §6.1).
2. 엔진 호출(§3 SKILL)로 산출 카드 확보 — 이 단계는 MBTI와 무관하게 그대로.
3. 내부 조력자(만세 할아버지/별이 할멈) 호출 시 산출 카드 + (있으면)`mbti_profile`을 함께 넘김. 어른은 **카드 필드로 해석 골격을 잡고, MBTI는 톤/조언 다듬기 힌트로만** 받음.
4. 삼신이가 감싸 전달 + 면책 2단.

### 3.4 "엔진-우선·단일 창구 위반 0" 확인 문장

> **본 설계는 삼신이 SKILL.md §0(엔진 산출만이 사주 근거) 위반 0, §7.5(단일 창구·새 user-facing 스킬 금지·페르소나 일관) 위반 0을 만족한다.** MBTI는 엔진 산출 카드와 물리적으로 분리된 자기보고 입력 레이어(`mbti_profile`)로만 존재하고, 사주 사실 근거로는 절대 쓰이지 않으며 오직 2층 해석의 톤·조언 개인화 힌트로만 참조된다. MBTI는 새로운 user-facing 스킬이 아니라 삼신이(saju-reading)가 내부에서 참조하는 모듈이며, 사용자 대면 화자는 여전히 삼신이 하나다. 엔진 카드 필드값을 MBTI가 덮어쓰거나 보정하는 경로는 존재하지 않는다.

## 6. 프로토타입 스펙 (개발 착수 가능 수준)

### 6.1 MBTI 입력 수집 흐름 (삼신이 보이스)

- **위치:** 사주 필수 입력(성별·음양력·생년월일·생시)을 다 받은 **뒤**, 엔진 호출 **전**. 선택 입력이므로 한 번만 가볍게 여쭙고, 모르면 바로 넘어감.
- **삼신이 보이스 예시(런타임 문구 — 개발이 그대로 쓰거나 변형):**
  - 물어보기: "아 참, 요즘 다들 안다는 그 MBTI — 혹시 네 것 아니? 알려주면 삼신이가 네 결에 좀 더 맞춰 풀어주마. 몰라도 괜찮단다, 그냥 넘어가면 돼."
  - 모름 위로: "모르면 안 넣어도 된단다. 그래도 보따리는 똑같이 펼쳐진단다."
  - 확인: "오냐, INTJ라고 했지? 그 결도 살짝 얹어서 봐주마."
- **입력 파싱:** 16유형 4글자 코드(E/I·S/N·T/F·J/P). 오입력·부분입력·"모름"은 `null` 처리(강등 없음).

### 6.2 데이터 구조/스키마

MBTI 프로파일은 엔진 산출 카드와 **별도 JSON 객체**로 관리(엔진 카드에 병합 금지):

```json
{
  "mbti_profile": {
    "provided": true,
    "type": "INTJ",
    "axes": { "EI": "I", "SN": "N", "TF": "T", "JP": "J" },
    "axis_strength": null,
    "source": "self_report",
    "note": "self-reported. NOT a saju fact. tone/advice personalization only."
  }
}
```
- `provided:false`이거나 객체 부재 시 → 해석 레이어는 MBTI 무시, 기존 풀이 그대로.
- `source`는 항상 `self_report` 고정(엔진 산출 아님을 스키마 레벨에서 못박음).
- `axis_strength`는 v2 후보(강도 슬라이더). MVP는 4축 코드만.

### 6.3 해석 레이어가 MBTI를 반영하는 방식 (규칙)

- 내부 조력자(만세 할아버지/별이 할멈)에게 산출 카드 + `mbti_profile`을 함께 전달.
- 조력자는 **해석 골격을 엔진 카드 필드로 먼저 완성**한 뒤, `mbti_profile.provided==true`면 **처방·조언의 "말투와 우선순위"만** MBTI 힌트로 다듬음. 골격의 사주 근거·필드 앵커는 불변.
- **가드(코드/프롬프트 레벨 강제):**
  1. MBTI 문자열이 "사주/오행/십신/신살/대운" 근거 문장에 등장하면 차단(분리 위반).
  2. "사주에 따르면 너는 [MBTI]" 패턴 금지(사주→MBTI 도출 차단).
  3. 네 글자 처방의 "└ 근거" 줄에 MBTI가 앵커로 등장 금지(엔진 필드만).
  4. MBTI 미제공 시 MBTI 언급 자체 금지.

경쟁이 "MBTI×사주 융합"을 이미 하고 있으므로, **결합 자체는 차별점이 아닙니다.** 삼신이의 차별은 구조에 있습니다:

1. **엔진-우선 결정론** — 대부분 경쟁이 LLM 생성에 의존(같은 사주에 매번 다른 팔자)하는데, 삼신이는 만세력 엔진이 사주팔자를 결정론으로 고정. "환각 점쟁이"가 아님. MBTI를 얹어도 **사주 사실은 흔들리지 않음**(분리 가드).
2. **캐릭터 페르소나(삼신이)** — 차가운 분석기가 아니라 다정한 견습 도사 한 목소리. 신생 경쟁(사주핑 등)이 캐릭터·관계형으로 오는 흐름과 정렬되면서, 삼신이는 **처음부터 캐릭터가 정체성**.
3. **낙인 없는 개인화** — MBTI를 판정·우열이 아니라 "조언을 더 편히 전하는 결"로만 씀. 유형 낙인 회피가 설계에 박힘.
4. **한 줄 훅:** "네 팔자는 그대로, 다만 네 결에 맞춰 더 다정하게 — 삼신이가 MBTI까지 살짝 얹어 봐주마."

### 7.3 유료화·상품 확장 여지

- **무료 훅 → 유료 심화:** MBTI 결합 개인화 체감이 무료 구간의 '더 맞다' 훅. 심화 풀이·저장·프로파일 지속(사주핑식 '나를 기억하는')은 유료 확장 후보.
- **AI 비용 주의(ai-product-manager §3.5):** MBTI 결합은 프롬프트가 길어져 **토큰 단위 비용이 증가**함(호출당 비용×사용량). 무료로 풀면 스케일 시 비용 부담 — 유료 설계에 토큰 경제 반영 필수 `[변동 가능 — 모델·단가 시점 의존]`.
- **글로벌 여지:** 경쟁(포춘토리)이 동양문화권 다국어 진출을 표방 `[추정 — 보도 기반]`. 삼신이도 페르소나·면책 로컬라이즈 시 확장 여지 있으나 이는 글로벌 팀장 협업 사안(범위 밖).
