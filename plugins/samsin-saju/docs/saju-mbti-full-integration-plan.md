## 핵심 설계 전환 요지 (30초 — 무엇을 유지하고 무엇을 융합으로 바꾸나)

현행은 **"분리 HARD-LOCK"** 계약이다: 성향(내부 MBTI)은 **사주 사실 근거가 절대 아니고**, 엔진 카드와 물리적으로 분리된 제3의 자기보고 레이어이며, 톤·조언의 말투와 순서만 다듬는다(`mbti-layer.md` §1·§3). 이번 "완전 융합"은 이 분리 잠금을 의도적으로 완화하되, **안전 바닥은 한 글자도 무너뜨리지 않는다.** 여기에 이번 개정은 **성향의 산출 방식을 'LLM 자기보고 레이어'에서 '결정론 성향 엔진 카드'로 승격**해, 융합을 **엔진×엔진 대칭**으로 다시 세운다. 표로 못 박는다.

| 구분 | 현행(분리·레이어×엔진) | 엔진×엔진 융합(이번 전환) | 유지/변경 |
|---|---|---|---|
| 사주 사실의 유일 근거 | 만세력 엔진 카드(`saju_engine.py` 산출) | **동일 — 엔진 카드만** | **유지(불변 바닥)** |
| **성향의 산출 방식** | LLM 자기보고 레이어 + 얕은 파싱(`mbti_util.py` 4글자·4축까지) — 성향 서술은 LLM 즉석 짐작 | **결정론 성향 엔진 `mbti_engine`이 성향 카드(스택·태그·clarity)를 규칙 산출**(LLM 개입 0). 성향 서술도 카드 룩업 기반 → **LLM 환각 여지 제거** | **변경(엔진 승격 · 핵심)** |
| 성향의 지위 | 별도 레이어·자기보고 참고값, 톤·순서만 | **엔진 산출 팩트(성향 카드)로 승격** — 한 해석·한 솔루션에 녹인 통합 렌즈(같은 문단에 사주+성향) | **변경(레이어→엔진 팩트)** |
| 사주↔성향 상호 도출 | 전면 금지(가드 1·2) | **여전히 금지** — "사주가 이러니 네 유형이…"·"유형이 이러니 사주에 관성이…" 금지. 두 카드는 각자 자기 근거만 | **유지(불변 바닥)** |
| 처방 근거 앵커(└ 근거) | 엔진 필드만(가드 3) | **사주 처방 근거는 여전히 사주 카드만**. 단 '전달 방식 근거'로는 성향 카드 인용 허용(부록 B §5.4 신규 경계) | **유지+경계 신설** |
| 유형코드·검사명 노출 | 표면 0(가드 5) | **여전히 0** — '성향결' 언어로만 | **유지(불변 바닥)** |
| 미제공 시 | 언급 0·강등 없음(가드 4) | **여전히 언급 0** — 성향 엔진이 `provided:false` 카드 내면 사주 단독 폴백 | **유지(불변 바닥)** |
| 면책 2단 | 강제 | **강제 유지** + 성향 단서(**이론 기반·임상검사 아님** 추가) | **유지+강화** |
| **정직 라벨** | "오락·참고"(자기보고) | **"오락·참고 + 자기보고 + 이론 기반 매핑 + 임상검사 아님"** — 재현성≠타당성 명문화(부록 B §4) | **변경(강화)** |
| 톤 지향 | 은은한 개인화 | **균형 가이드형**(명확한 방향 + 선택지·근거) | **변경(강화)** |

**한 줄 판정:** "엔진×엔진 융합 = **두 결정론 엔진(만세력·성향)의 카드 필드를 한 목소리로 짜** 구체 솔루션을 주되, 근거의 물리(사주 사실은 사주 카드 · 성향은 성향 카드)는 **각자 분리**를 유지한다." — 성향이 엔진 팩트로 올랐어도 **재현성이지 과학적 타당성이 아니며**(부록 B §4), 사주↔성향 상호 도출 금지는 불변이다. 이 문서는 이 경계를 9개 섹션 전체에서 지킨다.

## §1. 컨셉·포지셔닝

**슬로건(한 문장):**
> **"사주로 타고난 결, 성향으로 지금의 나 — 삼신이가 둘을 하나로 엮어 오늘 무엇부터 하면 좋을지 짚어준단다."**

**설명(3~5줄):**
삼신이는 만세력 엔진이 결정론으로 고정한 **타고난 결(사주 명식)**과, 사용자가 스스로 밝힌 **지금의 나(성향)**를 한 목소리로 엮어, "그래서 오늘·이번 주 무엇부터 하면 좋을지"라는 **구체적 방향과 선택지**로 착지시킨다. 점을 봐주는 것에서 멈추지 않고, 균형 가이드형 톤으로 명확한 방향을 주되 운명을 단정하지 않고 "이렇게 하면 유리하다 + 선택지 + 근거"로 전한다. 사주도 성향도 **오락·참고 목적**이라는 프레이밍은 처음부터 끝까지 유지한다.

**경쟁과의 차별점** (종합계획 §7 실데이터 근거 — 아래 근거 박스):
- **단순 사주앱 대비:** 대부분 경쟁 앱은 LLM 생성에 의존해 같은 사주에 매번 다른 팔자가 나온다("환각 점쟁이"). 삼신이는 엔진이 사주팔자를 결정론으로 고정하므로, 성향을 얹어도 **사주 사실은 흔들리지 않는다**(분리 가드).
- **MBTI 밈·유형 콘텐츠 대비:** "너는 T라서 이렇다"식 유형 낙인·우열 서술을 하지 않는다. 성향은 판정이 아니라 **"조언을 더 편히 전하고 방향을 구체화하는 결"**로만 쓴다. 낙인 회피가 설계에 박혀 있다.
- **결합 자체는 차별점이 아님(정직):** MBTI×사주 결합은 이미 실재하는 시장 트렌드다(포춘토리 2025-09, '운이온다' 2026-06 등). 삼신이의 차별은 결합이 아니라 **① 엔진-우선 결정론 ② 캐릭터 페르소나(삼신이) ③ 낙인 없는 개인화 ④ 구체 솔루션·방향성**이라는 구조다.

> 근거:
> - 내용: MBTI×사주 결합은 실재 시장 트렌드(포춘토리·'운이온다'·서적 '사주가 MBTI를 만나면'). "MBTI 사주" 직접 검색량은 낮아 공급 주도 트렌드. 삼신이 차별점은 결합이 아니라 엔진-우선 결정론+캐릭터+분리 가드 구조.

## §2. 융합 로직 (뼈대) — 엔진×엔진 대칭 결합

**두 결정론 엔진의 카드 필드를 하나의 해석으로 결합한다.** **사주 축 = 만세력 엔진 카드 필드(사주 사실의 유일 근거)**, **성향 축 = 성향 엔진 카드 필드(전달·솔루션 각도 렌즈 — 엔진 산출 팩트)**. 융합의 문법은 "사주 축이 **무엇을**을 정하고, 성향 축이 **어떻게·무엇부터**를 정한다"이다. 승격의 핵심은 성향 축 재료가 **'LLM 즉석 짐작'에서 '성향 엔진이 규칙 산출한 카드값(스택·태그·clarity)'로 바뀌어 환각 여지가 사라진 것**이다(성향 엔진 상세: 부록 B `docs/personality-engine-design.md`).

### §2.1 두 축의 재료 — 카드 × 카드

| 사주 카드 필드 (만세력 엔진 — 사주 사실) | 성향 카드 필드 (성향 엔진 — 렌즈 팩트) |
|---|---|
| `dayMaster`/`pillars`(일간·일주·팔자 8자) — 타고난 본바탕 | `axes`(E/I·S/N·T/F·J/P) — 4축 분해 |
| `fiveElements`(오행 분포·강약·과다·없는오행) — 기운 균형 | `traitTags`(의사결정·소통·에너지·실행 결) — 파생 성향 4결 |
| `tenGods`(십성) — 사회적 성향·재물·책임의 결 | `cognitiveStack`(주·부·3차·열등 기능) — 인지기능 스택 |
| `yongshin`(용신) — 나에게 약이 되는 기운 | `preferenceClarity`(축별 선호 명확도 0~1) — 얼마나 뚜렷한지 |
| `daewoon`/`sewoon`(대운·세운) — 큰 바람·올해 바람 | `dominantAxes`(가장 도드라지는 1~2축) — 어느 결부터 짚나 |
| `majorShinsal`(신살) — 특별한 기운 | `confidence`(신뢰도 — self_declared / quiz_derived) |

> **재료의 승격:** 현행은 성향 축이 '자기보고 4축 코드'까지였으나, 성향 엔진 승격 후 `cognitiveStack`·`preferenceClarity`가 새로 생겨 **"주기능이 뚜렷한 결(clarity 높음)"·"덜 익숙한 결(inferior)"까지 결정론으로 짚는다.** 단 낙인 없이(부록 B §4.2).

### §2.2 융합 매핑 원칙 (사주 카드 필드 → 성향 카드 필드)

각 사주 카드 필드가 "무엇을"을 말하면, 성향 카드 필드가 그 조언을 "어떻게 전하고 무엇부터 실천하나"로 굴절시킨다. **성향 카드는 사주 카드 필드값을 바꾸지 않는다.**

| 사주 카드 필드가 말하는 것 | 성향 카드 필드가 굴절시키는 것 | 융합 결과(한 문장 예) |
|---|---|---|
| `yongshin` = 물(水) 기운이 약이 된다 | `cognitiveStack.dominant`(큰 그림 결) → 의미·방향부터 / (감각 결) → 손에 잡히는 실천부터 | "네게 약이 되는 물 기운을, 큰 그림을 그리는 네 결이라면 '왜 필요한지'부터 품고, 손에 잡히는 걸 챙기는 결이라면 오늘 물 한 잔·산책부터 해보렴." |
| `tenGods`에 식상(표현·재주)이 도드라짐 | `traitTags.communication`(E결→나누며 / I결→혼자 정리해 꺼내며) | "표현하는 재주가 좋은데, 사람 사이서 기운 도는 결이면 모임에서, 혼자 곰곰 정리하는 결이면 글로 먼저 꺼내보렴." |
| `fiveElements`가 한쪽으로 과다·불균형 | `traitTags.execution`(J결→루틴·순서 / P결→마음 가는 것부터) | "치우친 기운은 차근차근 순서 정해(계획 결) 또는 오늘 마음 가는 하나부터(즉흥 결) 다독이면 된단다." |
| `daewoon`/`sewoon` 흐름이 바뀌는 시기 | `traitTags.decision`(T결→이유·원리 / F결→마음·관계 먼저) + `preferenceClarity`(뚜렷할수록 힘줘) | "흐름이 바뀌는 무렵엔, 따져 납득해야 편한 결이 뚜렷하니 '왜 그런지'부터 챙기며 준비하렴." |

### §2.3 결합 우선순위 — 충돌 시 무엇이 이기나 (HARD 규약 · 안전>사주엔진>성향엔진)

융합에서 사주와 성향이 부딪히면 **항상 사주 엔진이 이긴다.** 성향 엔진 팩트는 사주 엔진 팩트를 이길 수 없고, 안전 규칙은 두 엔진 둘 다 이긴다.

| 우선순위 | 이기는 것 | 규칙 |
|---|---|---|
| **1순위(최상)** | 안전 바닥 | 면책 2단·단정 금지·낙인 금지·중대결정 전문가 권유 — 두 엔진 어느 것도 이 위로 못 감 |
| **2순위** | **사주 엔진 팩트**(사주 카드) | 사주팔자·오행·십성·신살·대운·용신은 **오직 만세력 엔진 카드**. 성향 카드가 이 값을 덮어쓰거나 보정 불가 |

**충돌 예시 3종:**
- 성향 카드가 "혼자가 편한 결(I)"인데 사주 `tenGods`가 "사람과 어울릴 때 풀리는 재주"라면 → **사주가 이긴다.** "타고난 결은 사람 사이서 재주가 나오는데, 다만 혼자 정리할 틈을 곁들이면 네 결이 덜 지치겠구나"로 **사주를 사실로 두고 성향은 전달 방식으로만** 굴절.

- 안전과 성향이 부딪힐 때(예: 신살 낙인 위험) → **안전이 이긴다.** §7·10 신살 특례로 성향 미적용.

## §3. 솔루션·방향성 프레임워크

이 플러그인의 최종 강점은 "구체적 솔루션과 방향성"이다. 리딩을 **실행 가능한 방향**으로 전환하는 고정 6단 구조를 둔다. 이는 SKILL.md §4.3의 네 글자 처방(행동·습관·관계·피할 것)·필드 앵커·중대결정 안전장치를 **강화**하는 것이지 대체가 아니다.

### §3.1 고정 6단 솔루션 구조 (SOLVE 골격)

| 단계 | 무엇 | 원칙 |
|---|---|---|
| **① 현상 진단** | 지금 어떤 결/흐름인지 (사주 필드 + 성향 렌즈로 한 그림) | 엔진 필드가 보증하는 결 안에서만. 없는 사건 예언 금지 |
| **② 강점/제약** | 타고난 강점 1~2개 + 살짝 조심할 결 1~2개 | 강점 먼저(삼신이 정신). 제약은 공포 아닌 잔정 |
| **③ 3방향 선택지** | "이렇게 하면 유리 / 저렇게 하면 유리 / 그냥 두면" 갈림길 2~3개 | 단정 대신 선택지 + 각각의 근거 한 줄 |
| **④ 우선 1수** | 그중 오늘 가장 먼저 해볼 하나 | 성향 결에 맞춰(계획 결→순서 정해, 즉흥 결→마음 가는 것부터) |
| **⑤ 실행 팁** | 5~10분이면 할 작은 실천 + 꾸준히 들이면 좋은 버릇 | 네 글자 처방(§4.3)과 한 몸. 필드 앵커 |
| **⑥ 면책** | 1단 덕담 → 2단 정식 면책(+ 성향 단서) | 어떤 솔루션도 면책을 대체·약화 못 함 |

### §3.2 균형 가이드형 톤 규칙

담당자님 확정 톤을 문장 규칙으로 못 박는다.

- **단정 대신 방향 + 조건:** "반드시 ~된다" 금지 → **"~하면 유리하단다 / ~할 때 잘 풀리는 결"**. 명확한 방향은 주되 운명은 열어 둔다.
- **선택지 + 근거:** 방향을 하나만 던지지 않고 **2~3 선택지 + 각 근거 한 줄**을 준다(§3.1 ③). 결정은 사용자 몫으로 돌린다.
- **오락·참고 프레이밍:** "이런 기운이 있단다 / 참고삼아 품으렴"으로, "맞다·틀리다"가 아니라 결의 이야기로.
- **중대결정은 방향·마음가짐까지만:** 의료·법률·재무·결혼·이직·채용·계약은 "이런 마음가짐으로 준비하면 좋겠다"까지 + **전문가 권유**. "이 병이다 / 이 직장 가라 / 이 사람과 결혼하라 / 이 종목 사라" 절대 금지.
- **성향 낙인 금지:** "이 결이라 못한다"류 금지. 결은 우열이 아니라 다름.

> 근거:
> - 내용: 솔루션 6단 구조는 SKILL.md §4.3 네 글자 처방·필드 앵커·중대결정 안전장치·단정 회피(§5.2)를 강화. 균형 가이드형 = 방향+조건·선택지+근거·오락 프레이밍·중대결정 전문가 권유. Working Backwards 정신으로 "왜 사용자가 이 솔루션을 반길지"를 먼저.

## §4. 통합 리딩 출력 템플릿

### §4.1 문단 순서 (실제 답변이 나오는 순서)

```
① 다정한 인사 + (있으면) 이름 파동
② 타고난 결 — 사주 명식(일주·오행·십성)을 성향 렌즈와 한 그림으로 (융합)
③ 현상 진단 — 지금의 흐름(대운·세운) + 성향의 지금 결
④ 강점/제약 — 강점 먼저, 조심할 결은 잔정으로
⑤ 3방향 선택지 — 갈림길 2~3개 + 각 근거 한 줄
⑥ 우선 1수 — 성향 결에 맞춘 오늘 첫걸음
⑦ 🧧 네 글자 처방 — 행동·습관·관계·피할 것 (엔진 필드 앵커 · └ 근거)
⑧ 🌙 실행 팁·마무리 통찰 — 사주+성향을 다시 한 목소리로
⑨ 1단 삼신이 덕담
⑩ 2단 정식 면책 + 성향 단서(성향 반영 시)
```

> 현행 확장 스펙(§2.2)은 성향을 "네 글자 처방 뒤·면책 앞 **별도 문단**"으로 분리했다. **완전 융합에서는 ②~⑧ 본문 안에서 사주와 성향을 한 목소리로 짜되, ⑦ 네 글자 처방의 `└ 근거`만은 여전히 엔진 필드만**으로 둔다(가드 3 불변). 즉 "서술은 융합, 근거 앵커는 분리"가 융합판 출력의 핵심 규칙이다.

### §4.2 통합 리딩 예시 문단 (가상 인물 · 사주 요소 + 성향 요소가 한 문단에 섞인 예)

> **가상 인물:** '지우'(가명). 엔진 산출 카드 = 을목(乙木) 일간, 오행에서 물(水)이 약하고 불(火)이 과다, 십성에 식상(표현·재주) 도드라짐, 용신 = 물(水). 자기보고 성향 = 큰 그림부터 그리는 결(N) + 마음 가는 대로가 편한 결(P). *(엔진 카드값·성향은 예시용 가상값 — 실제 풀이는 엔진 산출 카드에서만 온다.)*

---

아이고 지우야, 어디 보자… 네 본바탕은 **을목(= 여린 새싹 같은 나무 기운)**이란다. 부드럽게 뻗되 꺾이지 않고 감아 오르는 결이지. 그런데 네 보따리를 펼쳐 보니 **불 기운이 좀 넘치고 물 기운은 여려서**, 마음이 확 타올랐다가 금세 마르는 날이 있겠구나 — 그럴 때 **네게 약이 되는 건 물 기운**이란다(용신). 마침 네겐 **표현하고 만들어내는 재주(식상)**가 도드라지는데, 넌 큰 그림부터 그리는 결이라 "이걸 왜 하지, 어디로 가지"부터 잡히면 신이 나는 사람이야. 그러니 삼신이 한마디 — 재주를 꺼낼 땐 세세한 계획표에 너무 매이지 말고(넌 마음 가는 대로가 편한 결이니), **먼저 '이 일이 내게 어떤 의미인지' 큰 그림 한 줄만 적어 두고, 그다음 오늘 마음 가는 것부터 툭 시작**해보렴. 약이 되는 물 기운은 거창하게 말고 오늘 물 한 잔 더, 저녁 산책 십 분 — 그거면 충분하단다. 다 못 해도 괜찮아, 결은 우열이 아니라 그저 다름이니까.

---

*(위 문단에서 사주 요소 = 을목 일간·불 과다/물 약함·식상·용신 물 [모두 엔진 카드 대응]. 성향 요소 = 큰 그림 결(N)·마음 가는 대로 결(P) [자기보고 렌즈]. 둘이 "재주를 어떻게·무엇부터 꺼내나"라는 한 솔루션으로 엮였고, 사주 사실을 성향이 덮어쓰지 않았으며, 유형코드·검사명은 노출되지 않았다.)*

### §5.1 티어별 융합 규칙

- **T1 풀(01·02·03·06·07·08·13·14):** 본문 ②~⑧에서 사주+성향을 한 목소리로 융합, 3방향 선택지·우선 1수까지 풀세트.
- **T2 라이트(04·05·09·11):** 서사·묘사 구간엔 성향 0. 맺음·다스리는 법·마음가짐 구간에만 1~2문장. 순화·몰입 우선.
- **T3 특례(10·12):** 10은 신살 특례 하드 가드(§5.3), 12는 초경량(짧게 유지).

### §5.2 채용15 제외 판단 (유지)

**판정: 채용참고(15)는 융합에서도 계속 제외한다.** 성향(MBTI) 기반 유형 스크리닝은 채용 차별 위험을 사주 단독보다 **가중**한다("이 유형이라 협업 부적합"은 게이트 0 verdict·차별과 정면 충돌). 15는 이미 이중 게이트로 최고위험 관리 중이며, 융합은 이 위험을 키운다. **이 예외는 담당자님·법무 승인 없이 열지 않는다** ⚑(§7 R4).

### §5.3 10 신살풀이 특례 (낙인 리스크 최상)

신살(백호·괴강·원진 등)은 그 자체로 '센 살' 낙인 소재다. 여기에 성향을 결합하면 **"이 성향이라 이 살이 세다 / 이 살 때문에 이런 성향"**이라는 이중 낙인이 태어난다 — ai-product-manager 위험 등급 **'높음'**(실질 심리 피해). 완전 융합에서도 10은:
1. **신살↔성향 연결 문장 전면 금지** (한 문장·한 문단에 두지 않음)
2. 성향은 **'살 다스리는 법' 처방의 말투에만** 극소
3. **별도 결합 문단 없음** — 못 지킬 바엔 성향 미적용(생략)이 안전 기본값

## §6. 입력·UX 흐름

### §6.1 융합에 필요한 입력 — 두 엔진 각자 입력

| 입력 | 필수 | 흐르는 곳 | 비고 |
|---|---|---|---|
| 성별 | 필수 | 만세력 엔진 | 대운 순역 결정 |
| 음양력(+윤달) | 필수 | 만세력 엔진 | 만세력 기준 |
| 생년월일 | 필수 | 만세력 엔진 | — |
| 생시(12지지/모름) | 권장 | 만세력 엔진 | 모름이면 시주 의존 풀이 "미상" |
| **성향 — 유형 직접(4글자)** 또는 **약식 문항** | **선택** | **성향 엔진** | 융합 렌즈. 성향 엔진이 성향 카드 산출. 없으면 사주 단독 폴백 |

**입력 순서:** 사주 필수 입력을 다 받은 **뒤**, 두 엔진 호출 **전**에 성향을 선택 입력으로 한 번만 가볍게 여쭌다. 유형을 알면 직접(경로 a), 모르면 약식 문항(경로 b) — **둘 다 성향 엔진 `build_mbti_card()`로 같은 성향 카드에 수렴**(부록 B §2.2). 결과 출력 표면 문구는 '성향' 언어로만(유형코드 복창 금지 — 입력 폼에서만 유형코드 노출 허용).

### §6.2 MBTI를 모르는 사용자 처리 (성향 엔진 2경로 폴백)

- **① 약식 문항(경로 b · 선택 제공):** 성향을 "모른다"는 사용자에게, 강제하지 않고 삼신이 보이스로 **4축 각 1~3문항**을 가볍게 제안할 수 있다(예: "사람들 사이서 기운이 도는 편이니, 혼자 있을 때 편한 편이니?"). 답하면 **성향 엔진이 축별 점수·선호 명확도(clarity)를 결정론 산출**(부록 B §3.4 산식)해 유형+강도까지 성향 카드로 만든다 — LLM 짐작이 아니라 룩업·산술. **이 문항은 오락·자기이해 참고이며 성격검사·과학적 진단이 아님**을 프레이밍으로 깐다. ⚑ 문항 설계·"검사 아님" 고지 문구는 법무 검토 자리(§7 R6 연계).
- **② 스킵 시 사주 단독 폴백:** 문항도 건너뛰면 성향 엔진이 `provided:false` 카드를 내고, **성향 없이 사주 단독 풀이가 그대로** 나온다(강등·오염 0 — 가드 4). 융합 문법은 사주 축만으로도 완결되게 설계한다("성향은 있으면 더 구체화, 없어도 방향은 준다").
- **input-form.html 연동:** 현행 폼의 "몰라요" 경로에 약식 문항(경로 b)을 붙인다 — "몰라요" 누르면 4축 문항을 띄우고, 답하면 `mode:quiz`로 성향 엔진 호출(부록 B §6.4). 유형 직접 선택은 `mode:type`.

### §6.3 조력자 소관 조정 (그룹 A/B)

현행은 그룹 A(만세 할아버지 `samsin-mansae` — 명리·실용 9메뉴)와 그룹 B(별이 할멈 `samsin-byeolnim` — 신당·서사 6메뉴)가 카드 필드만 근거로 해석 골격을 잡는다. 융합에서는:
- **소관 자체는 유지** — 그룹 A/B 분담·단일 창구(화자는 삼신이 하나)는 그대로.
- **두 카드를 함께 전달** — 라우터가 `saju_engine` 카드와 (있으면) `mbti_engine` 성향 카드를 **나란히** 조력자에게 넘긴다(두 카드 물리 분리 유지·병합 금지). 조력자는 사주 카드로 골격을 먼저 완성한 뒤, 성향 카드가 있으면 **본문에 녹이는 융합 규칙(§2·§3)**과 티어(§5)를 적용. 그룹 B는 서사 구간 성향 0·10 특례를 특히 준수.
- **미확인:** 조력자 파일(`agents/samsin-mansae.md`·`samsin-byeolnim.md`) 본문은 이번에 Read하지 못함 — 실제 배선 문구는 개발 착수 시 조력자 파일 확인 후 확정(추측 금지).

## §7. 리스크·안전·개인정보 거버넌스

완화된 융합에서도 지킬 **새 가드(안전 바닥)**를 명시한다. 종합계획 R1~R6를 계승하되, "서술 융합"이 새로 만드는 위험에 대응한다.

| 리스크 | 엔진×엔진이 키우는 지점 | 새 가드(안전 바닥) | 법무 |
|---|---|---|---|
| **R1 유사과학 단정 (엔진화로 가중)** | 성향이 **엔진 산출 팩트**로 오르면 "성향을 과학적으로 판정하는 검사"로 오인 위험이 커진다 — 승격이 만드는 **최대 새 리스크** | **재현성≠타당성 명문화**(부록 B §4·§7.1). 성향 엔진 결정론은 재현성뿐, 융 유형론 기반 이론 매핑임을 카드 `meta.note`·2층 면책에 못 박음. 오락·참고 + **이론 기반 + 임상검사 아님** 4중 라벨. 유형코드·검사명 노출 0. 단정 금지("반드시 ~된다" → "~하면 유리") | **검토 ⚑** |
| **R2 유형 낙인 (스택 승격으로 가중)** | 인지기능 스택(특히 `inferior` 열등기능)이 "약점·못하는 것" 판정으로 샐 위험 | 낙인 회피 루브릭 100%. inferior는 "덜 익숙한 결"까지만(부록 B §4.2). "우열 아닌 결의 차이"만. 태그 라벨 고정 문구. 10 신살·그룹 B 특히 | — |

| **R5 성향 입력 신뢰도** | 자기보고라 틀릴 수 있음 | **선택 입력**. 엔진 팩트로 승격돼도 **재현성 팩트지 사주 사실과 동급 아님**(2순위 사주 > 3순위 성향). 문항 경로는 `clarity`로 뚜렷함 정도를 담아 과단정 눅임. 없으면 사주 단독 폴백 | — |
| **R6 개인정보 (엔진화로 밀도↑)** | 성향 엔진이 **구조화 프로파일(스택·태그·clarity·문항 원응답)**을 만들어 정보 밀도·민감도가 오른다 | **세션 비영속 기본 유지.** 문항 원응답은 카드 산출 후 **즉시 폐기 권장**(카드만 세션 보유). 저장·프로파일링 시 개인정보 처리 고지·동의(부록 B §4.3) | **검토 ⚑** |

### §7.1 안전 가드 4대 명시 항목 (엔진 승격 반영)

- **★재현성 ≠ 과학적 타당성 (엔진 승격 핵심 · 신규 명문화):** 성향 엔진이 성향을 결정론 카드로 산출해도, 이 결정론은 **"같은 입력→같은 카드"라는 재현성일 뿐 과학적 타당성 보증이 아니다.** 만세력 결정론은 확립된 역법 계산이지만, 성향 엔진은 **융(C.G. Jung) 심리유형론 기반 이론 매핑**이다(psychologist 정합 — 명명된 프레임 + 이론 한계 명기). 성향 엔진을 **'과학적 검사'로 격상하는 표현 전면 금지** — 카드 `meta.note`(자기보고·이론 기반·임상검사 아님)와 2층 면책이 이 라벨을 못 박는다(부록 B §4.1). 재현 가능한 이론 기반 매핑으로만 규정한다.
- **개인정보 (엔진화로 갱신):** 성향 엔진은 스택·태그·clarity·(문항 경로 시)원응답까지 만들어 **정보 밀도가 오른다.** 성향 카드 + 생년월일 결합은 **세션 비영속이 기본**이고, **문항 원응답은 카드 산출 후 즉시 폐기 권장**(카드만 세션 보유). 저장·재사용·프로파일링·문항 응답 저장은 개인정보 처리방침·동의 흐름이 선행돼야 하며, 이는 **법무 검토 항목 ⚑**(§7 R6·부록 B §4.3).
- **단정 금지:** 운명 단정("반드시 ~된다")·특정 날짜 사고/사망 예언·질병명 단정·재무 확정("이 종목 사라")·이직/결혼/채용 가부 단정 전면 금지. 성향도 "너는 반드시 이렇다" 금지 → "이런 결이 뚜렷한 편"(clarity 반영). 방향·마음가짐까지만 + 전문가 권유.
- **면책 2단 유지:** 모든 융합 풀이 끝에 **1단 삼신이 덕담 → 2단 정식 면책(원문 그대로)**. 성향 반영 시 성향 단서(이론 기반·임상검사 아님 추가). 어떤 융합 솔루션도 면책을 대체·약화 못 함(HARD-GATE).

### §7.2 법무 정식 검토 필요 항목 (⚑)

- **⚑ R1** — 성향 엔진 '과학적 검사 아님' 라벨(`meta.note`·면책)의 법적 적부: 성향 엔진 결과가 유사과학·과학적 진단으로 오인되지 않도록 하는 고지 문구.
- **⚑ R4** — 채용참고(15) 성향 결합: 담당자님·법무 승인 없이 열지 않음.
- **⚑ R6** — 성향 카드(스택·태그·clarity)·문항 원응답·생년월일 저장·프로파일링: 개인정보 처리방침·동의 흐름 + 문항 원응답 즉시 폐기 정책 문서화.
- **⚑ 약식 문항 프레이밍** — "성격검사 아님·오락 참고" 고지 문구 법적 적부.
- 위 항목의 법령 근거·면책 최종 문구는 **법무 팀장이 확정**하며, 본 기획안은 자리만 표식한다(전략팀 직접 확정 안 함).

## §8. 단계별 실행 로드맵

가설 검증 척추(종합계획 §1)를 유지한다 — 완전 융합은 아직 **검증되지 않은 가설**이므로 값싸게·빠르게 검증 후 확장한다.

| Phase | 범위 | 산출물 | 게이트(통과 조건) |
|---|---|---|---|
| **Phase 1 — 파일럿** | 융합 렌즈 2~3메뉴(추천 07 직업운·08 결혼연애·02 올해운세 — 조언이 성향에 민감·그룹 A로 리스크 낮음) | 융합 출력 템플릿 배선 + 평가셋 100건 | §8.2 확률적 합격선 통과 + **분리 준수 0 위반** |
| **Phase 2 — 전체** | 그룹 A T1(01·03·06·13·14) → 그룹 B T2(04·05·09·11) → T3(10·12) 순차 | 14메뉴 융합 배선 + 티어별 회귀 평가 | 티어별 낙인·표현 전환 100% |
| **검증** | A/B(성향 있음/없음) + 온라인 모니터링 | H1·H2 지표 리포트 | §9 지표 최소 성공 기준 |

### §8.1 각 단계 산출물·게이트 상세

- **Phase 1 산출:** 융합 출력 템플릿(§4) 실배선 · 평가셋(같은 사주 카드 × 성향 신호 × 파일럿 메뉴) · 마이크로 서베이 1문항.
- **Phase 1 게이트:** 표현 전환(유형코드 노출 0) 100% · 분리 준수(성향이 사주 근거로 안 샘) 100%(0 허용) · 낙인 회피 100% — **하나라도 위반이면 확장 중단·회귀(No-Go).**
- **Phase 2 게이트:** 그룹 B·10 신살에서 서사 몰입·낙인 회귀 0.

### §8.2 확률적 검수 기준 (AI 기능 — 통과/실패 아닌 통과율)

성향 융합은 **같은 입력에 매번 조금씩 다른 출력**을 내는 확률적 기능이므로, 통과/실패 이분법이 아니라 **평가셋 통과율·루브릭**으로 검수한다.

## §9. 성공 지표

가설을 검증 가능한 형태로(종합계획 §1.1 계승):
> **H1(개인화·솔루션 체감):** 융합 풀이는 사주 단독보다 '나에게 맞춘 느낌 + 무엇부터 할지 알겠다'를 유의하게 높인다.
> **H2(상품성·유지):** 융합 풀이를 받은 사용자는 재방문·추가 메뉴·공유 의향이 높다.

| 지표 | 정의 | 현재값 | 목표 `[변동 가능]` | 측정 방법 | 가설 |
|---|---|---|---|---|---|
| **M1 개인화 체감** | "이 풀이가 나에게 맞춘 느낌" 5점 | 미측정 | 실험군 > 대조군(유의차) | 풀이 끝 1문항 마이크로 서베이(삼신이 보이스) | H1 |
| **M2 솔루션 유용도** | "무엇부터 하면 좋을지 알겠다" 5점 | 미측정 | 실험군 > 대조군 | 마이크로 서베이 1문항(융합 강점 직접 측정) | H1 |
| **M3 융합 루브릭 점수** | 사주+성향이 한 솔루션으로 엮였는지 0~2점×5기준 | 미측정 | 평균 1.4/2.0+ · 분리준수 100% | 내부 평가셋 채점(사람+AI) | H1 |
| **M4 재방문·추가이용률** | 첫 풀이 후 N일 내 재방문/추가 메뉴 | 미측정 | 실험군 > 대조군 | 세션 로그(익명 집계) | H2 |
| **M5 공유/저장 의향** | "친구에게 보여주고 싶다" 비율 | 미측정 | 실험군 > 대조군 | 마이크로 서베이 선택 문항 | H2 |

**측정 방법(A/B):** 동일 사용자군을 **대조군(사주 단독)** vs **실험군(융합)**으로 나눠 같은 파일럿 메뉴에서 M1~M5 비교. **교란 통제** — 두 군의 엔진 산출은 동일(차이가 오직 성향 융합에서만 오도록), 텍스트 길이·이모지 등 표면 변수 통제.

**최소 성공 기준(Go/No-Go):** M1·M2 실험군 우세(방향성 + 정성 코멘트 우세) `[임계값은 파일럿 표본으로 확정]` · **M3 분리 준수 100케이스 중 100건(0 허용)** · **No-Go 신호 = 분리 준수 위반 1건이라도 발생 시 확장 중단·회귀.** 융합 체감 차이가 무의미하면 결합 가치 재검토.

**토큰 비용 표식 `[변동 가능]`:** 융합은 프롬프트가 길어져 **호출당 토큰 비용이 오른다**(호출당 비용 × 예상 사용량). 무료로 풀면 스케일 시 비용 부담 — 유료 설계에 토큰 경제 반영 권고. 단가는 모델·시점 의존.

## 부록 A. 거버넌스 위반 0 확인 문장

> **본 융합 기획안은 삼신이 SKILL.md §0(엔진 산출만이 사주 근거) 위반 0, §4.3(깊이·처방·중대결정 안전장치) 정합, §5(면책 2단 강제) 위반 0, §7.5(단일 창구·새 user-facing 스킬 금지·페르소나 일관) 위반 0을 유지한다.** 완전 융합은 **서술의 문법(사주와 성향을 한 목소리로 짜 구체 솔루션을 준다)만 결합**하고, **근거의 물리(사주 사실 = 엔진 카드 · 성향 = 자기보고 렌즈)는 분리를 유지**한다. 성향은 엔진 카드 필드값을 덮어쓰거나 보정하지 않고, 사주↔성향 상호 도출은 금지되며, 처방 `└ 근거`는 엔진 필드만, 유형코드·검사명은 사용자에게 노출되지 않고, 미제공 시 사주 단독 폴백으로 강등·오염이 없다. 채용참고(15)는 차별 리스크로 융합 대상에서 계속 제외된다. 사용자 대면 화자는 여전히 삼신이 하나다.
